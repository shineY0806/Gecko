## 第 1 章 · 三分钟上手

### 1.1 这个工具是干什么的

你给它一个网址，它会自动把这个网站「翻一遍」，然后告诉你：

- 这个站一共有哪些页面、哪些地址会返回 404
- 哪里藏着登录框、后台地址、备份文件、接口地址（这些通常是最值得看的地方）
- 页面里有哪些表单、表单要提交到哪个地址、需要填哪些字段
- 页面源码的注释里有没有提示（靶场经常把线索写在注释里）
- 引用了哪些外部 JS / CSS / 接口

最后把这些整理成一份报告，存在你电脑上的一个文件夹里。

**它不会做的事**：不会破解验证码、不会绕过 WAF、不会攻击网站。它是「侦察记录员」，不是「攻击工具」。

### 1.2 第一步：启动

双击 **`Gecko.exe`**（约 58MB，体积较大是因为已经把浏览器渲染内核一起打包进去了）。

它会自己弹出一个独立窗口，就是工具的主界面。**不需要装 Python，也不需要装任何东西。**

> 三个小提示：
> - 第一次打开时杀毒软件可能提示"未知程序"，选择允许即可。这是因为程序是我们自己打包的、
>   没有购买数字签名，不是病毒。
> - 想放桌面：在 exe 上点右键 →「显示更多选项」→「发送到」→「桌面快捷方式」，
>   以后双击桌面图标就行，也可以直接拖到任务栏固定。
> - 界面本质是个本地服务，地址是 `http://127.0.0.1:8765`。万一窗口没弹出来，
>   把这个地址复制到浏览器打开也能用。

<details>
<summary>备用启动方式（适合想改代码的人）</summary>

如果电脑上已经装了 Python，也可以双击 `启动Gecko.bat` 用源码方式启动，
它会自动创建 `.venv` 环境并装依赖（首次约 1～3 分钟）。改了代码后想重新打包成 exe，
执行 `python tools/build_exe.py` 即可（见文末「附：重新打包 exe」）。
</details>

### 1.3 第二步：填网址并开始

在主界面上方找到「目标 URL」，填上要爬的地址，例如：

```
http://127.0.0.1:8000
```

然后点击「开始爬取」。

想先练手的话，可以先用本项目自带的演示站：

```powershell
cd demo_site
python -m http.server 8000
```

然后爬 `http://127.0.0.1:8000`。演示站里刻意埋了注释提示、登录框、备份文件路径等，适合熟悉报告长什么样。

### 1.4 第三步：看结果

爬完后切到「报告文件」标签页，就能看到生成的文件，点文件名可以在线预览，也可以下载。

最重要的两个：

| 文件 | 是什么 | 建议 |
|---|---|---|
| `report.md` | 人话版的报告摘要 | **先看这个**，用记事本/浏览器打开就能读 |
| `report.json` | 完整数据，供程序处理 | 需要二次分析时用它 |

其他文件的作用见「第 3 章」。

## 第 2 章 · 界面怎么看

主界面分左右两侧：左边是参数，右边是结果标签页。

### 2.1 左边：参数区

| 参数 | 大白话 | 一般怎么填 |
|---|---|---|
| 目标 URL | 从哪个地址开始爬 | 必填 |
| 输出目录 | 报告存哪 | 留空即可，自动生成 `output_<主机名>` |
| 抓取方式 | 用普通请求还是真浏览器 | 默认「普通 HTTP」，抓不到内容再换 |
| 每域名并发 | 同时最多发几个请求 | 新手保持 0；怕把站点压垮就填 2～5 |
| 爬取深度 | 从首页往下翻几层 | 2～3 够了，太大容易没完没了 |
| 线程数 | 几个人同时干活 | 5 左右；太大容易被对方限流 |
| 请求间隔 | 每次请求之间歇几秒 | 0 = 不歇；对方有防爬就填 0.5～1 |
| 最大页面数 | 最多抓多少页就收工 | 默认 500，先小后大 |
| 超时 / 重试 | 等多久算失败、失败重试几次 | 保持默认 |
| Cookie | 登录后的身份 | 需要爬登录后页面才填 |
| 代理 | 换个 IP 出口 | 一般不用 |

**三个勾选项**（建议都勾上，无害）：

- 自适应限速：发现网站变慢就自动放慢，不容易把人家搞挂
- 断点续爬：中途关掉再跑一次，能从上次停的地方继续
- 响应缓存：反复调参数时，不再重复请求对方网站

### 2.2 右边：结果标签页

| 标签页 | 看什么 |
|---|---|
| 概览 | 抓了多少页、状态码分布、深度分布，一眼看全 |
| 日志 | 实时滚动的过程记录，报错也在这里 |
| 页面 | 每个页面的地址、状态码、标题 |
| 表单 | 发现的表单、提交地址、字段名 |
| 敏感路径 | 命中关键词的地址（登录/后台/备份/接口等），**优先看这里** |
| 注释 | 页面源码里的注释内容 |
| 站外引用 | 引用了哪些外部地址 |
| 报告文件 | 所有产出文件，可预览/下载 |

## 第 3 章 · 生成的文件都在讲什么

一次爬取会在输出目录（默认 `output_<主机名>`）里生成这些文件：

| 文件 | 内容 | 什么时候看 |
|---|---|---|
| `report.md` | 报告摘要（人话版） | 每次先看它 |
| `report.json` | 全部数据 | 要做程序分析时 |
| `urls.txt` | 发现的所有地址 | 想导出地址清单时 |
| `interesting.txt` | 命中敏感关键词的地址 | 找突破口时 |
| `forms.csv` | 表单清单（地址/提交方式/字段） | 用 Excel 打开最方便 |
| `comments.txt` | 源码注释 | 靶场找提示时 |
| `items.csv` / `items.json` | 你自己定义的字段提取结果 | 只有配了「自定义字段提取」才有 |
| `media.csv` / `media.json` | 发现的媒体源地址（类型/来源页/发现方式） | 只有开了「媒体源发现」才有 |
| `images.csv` / `images.json` | 发现的图片地址（类型/来源页/发现方式/说明文字） | 只有开了「图片发现」才有 |
| `images/` 目录 | 下载回来的图片 | 只有开了「图片下载」才有 |
| `media/` | 下载回来的媒体文件 | 只有同时开了「媒体下载」才有 |
| `visited.json` | 已抓过的地址 | 下次运行自动跳过，别手动改 |
| `checkpoint.json` | 断点位置 | 开了断点续爬才有，全爬完自动删除 |
| `.cache/` | 响应缓存 | 想强制重新抓就删掉这个文件夹 |

> 小技巧：output 目录里带点的文件夹（`.cache`）和 `visited.json` 决定了「哪些不用再抓」。
> 想完完全全重新爬一次，用命令行加 `--fresh`，或者直接换个输出目录。

## 第 4 章 · 几个进阶功能，分别什么时候用

这一章的功能**默认都不开**，按需要再开。

### 4.1 浏览器渲染（抓取方式 = 浏览器渲染 / 反检测浏览器）

**什么时候需要**：你用浏览器打开明明能看到内容，但爬下来却是空的 —— 说明内容是 JS 现生成的，
此时普通 HTTP 抓取看不到。

**怎么用**：界面上把「抓取方式」改成「浏览器渲染」。

**首次使用要额外装一次浏览器内核**（约 150MB，只需一次）：

```powershell
python -m playwright install chromium
```

装完重启工具即可。没装的话界面上这个选项会是灰的，并提示安装命令。

**两种模式怎么选**

| 模式 | 说明 | 速度 |
|---|---|---|
| 动态渲染（dynamic） | 真浏览器打开页面，能拿到 JS 生成的内容 | 慢一些 |
| 反检测（stealthy） | 在真浏览器基础上抹掉自动化痕迹，应对指纹检测 | 最慢 |

**配套两个小参数**（选了渲染才出现）：

- 等待元素出现：填一个 CSS 选择器（如 `.list-item`），等到它出现再取页面
- 等网络空闲：页面还在异步加载数据时勾上，更完整但更慢

### 4.2 自定义字段提取

想把页面上的某些内容结构化抓下来（比如所有商品标题和价格），在「自定义字段提取」里每行写一条：

```
标题=h1
价格=.price
```

等号左边是你起的名字，右边是 CSS 选择器。结果会写进 `items.csv` / `items.json`，可以直接用 Excel 打开。

**CSS 选择器怎么知道？** 在浏览器里右键你想抓的内容 → 检查 → 在高亮的代码上右键 → Copy → Copy selector。

### 4.3 断点续爬

大站一次爬不完，或者中途要关机。勾选「断点续爬」后：

- 每爬完一层就自动存一次进度
- 中途关掉窗口 / 按 Ctrl+C 中断，进度都不会丢
- **再次运行同样的配置**，会自动从断点继续，不会重复抓已经抓过的
- 全部爬完后断点文件自动删除

### 4.4 响应缓存

调参数时会反复跑同一个站。勾选后第二次起直接读本地缓存，既不打扰对方，速度也快得多。
想重新抓就把输出目录下的 `.cache` 文件夹删掉。

### 4.5 自适应限速

不用自己猜该歇几秒。工具会盯着响应时间：对方变慢就自动放慢，恢复了再提速。
比写死一个间隔更不容易把靶场打挂。

### 4.6 每域名并发

一次发现上千个地址时，默认会并发猛抓。填 2～5 可以给对方留余地，也不容易触发限流。

### 4.7 指纹伪装（HTTP 后端 / 浏览器指纹）

有些站点会检查「你是不是真的浏览器」。把 HTTP 后端选成 `curl_cffi`、指纹选 `chrome`，
工具发出的请求在 TLS/HTTP2 层面就和真 Chrome 一样。

### 4.8 媒体源发现（`--media-scan`）

页面上挂着的视频/音频，地址往往不写在明面上：有的在 `<video src>`，有的藏在 `<source>` 的多码率回退里，
还有相当一部分是播放器初始化时由 JS 变量塞进去的。勾选「媒体源发现」或加 `--media-scan`，
工具会把这些地址挨个挑出来，写进 `media.csv` / `media.json`。

能认出的写法：

| 写法 | 例子 | 识别为 |
|---|---|---|
| `<video src="…">` | `<video src="/a.mp4">` | `video@src` |
| `<source>` 回退 | `<source src="x.m3u8" type="application/x-mpegURL">` | `source@src` |
| `<audio>` / `<embed>` | `<audio src="b.mp3">` | `audio@src` / `embed@src` |
| 内联 JS 硬编码 | `var p={hls:"https:\/\/a.com\/x.m3u8"}` | `js-inline` |

按扩展名分成五类：`hls`(m3u8)、`dash`(mpd)、`file`(mp4/webm/flv/mov)、`segment`(ts/m4s)、`audio`(mp3/m4a/aac…)。
JS 里的转义斜杠 `https:\/\/…` 会自动还原，站内相对路径 `/assets/clip.mp4` 会补成绝对地址。
同一个地址被多个页面或多种写法命中时合并成一行，并记录命中次数，不会刷出一堆重复。

> **能不能下载，取决于你对该内容是否有合法权利**（自有内容、已获授权、
> 或明确允许下载的公共领域/CC0 素材）。Gecko 不替你做这个判断。

#### 要把源下载回来：`--media-download`

v1.6.1 起，勾上「媒体源发现」后再加 `--media-download`，工具会把清单里的地址真正取回来。
`--media-dir` 指定保存目录（默认 `<输出目录>/media`），`--media-max-mb` 设单文件体积上限。

两条链路自动分流：

| 源类型 | 做法 |
|---|---|
| HLS（`.m3u8`） | 解析 master 选码率 → 并发拉分片（6 线程）→ 二进制拼接 → ffmpeg `-c copy` 合并成 mp4 |
| 直链（mp4/webm…） | Range 断点续传 + 流式写盘（64KB 一块）+ 边下边算 SHA256 |

大文件的四条保证：① 流式写盘，**1GB 实测内存峰值 60MB**，不随文件增大；
② 残片只在服务端支持 Range 时续传，不支持就删掉重头——**绝不追加**；
③ `.part` 中间文件 + 原子改名，中断不会留下「看起来已完成」的文件；
④ 写完校验长度与哈希，不信任 Content-Length。

> 为什么不用朴素写法：中断后直接全量 GET 再追加到残片，会得到 1.29GB 的坏文件
> ——体积更大但内容错位，SHA256 对不上，还白白重下 1GB。实测对比见版本记录。

也可以单独当下载器用：

```powershell
python gecko/core/media_download.py "https://example.com/a.m3u8" -o videos
python gecko/core/media_download.py --from media.csv -o videos --types hls,file
```

### 4.9 图片发现与下载（`--image-scan` / `--image-download`）

**v1.7.0 起。** 在此之前 Gecko 对图片是视而不见的：只解析 `scripts` / `styles` / `frames`，
`<img>` 压根不收集，渲染模式下还会主动拦掉图片请求来提速。

现代站点的图片很少老老实实写在 `src` 上，所以一共认六种写法：

| 写法 | 记成 |
|---|---|
| `<img src>` | `img@src` |
| 懒加载 `data-src` / `data-original` / `data-lazy-src` / `data-echo` | `img@data-src` 等 |
| `srcset` 多分辨率 | `img@srcset`，挑尺寸最大的那个候选 |
| `<picture><source srcset>` | `source@srcset` |
| 内联 CSS `background-image: url(...)` | `css-bg` |
| OG / Twitter 分享图 | `meta@og:image` |

几条规则：

- **base64 内联图（`data:image/...`）自动跳过**——它不是一个能单独下载的地址
- 只认常见图片扩展名：`jpg` / `png` / `gif` / `webp` / `avif` / `bmp` / `svg` / `ico` / `tiff`
- 同一地址被多个页面、多种写法命中时**合并成一行**并记录命中次数（跟媒体源一个逻辑）
- `srcset` 里按描述符挑最大的（`2x` 大于 `1x`），没有描述符时取最后一个

开启方式：`--image-scan` 只发现，产出 `images.csv` / `images.json`；
再加上 `--image-download` 才真正落盘，`--image-dir` 指定目录（默认 `<输出目录>/images`），
`--image-max-mb` 设单张上限。

下载复用 v1.6.1 的大文件链路（流式写盘 + Range 断点续传 + `.part` 原子写），
所以大图下到一半断了，再跑一次同一条命令会接着下，不会从头重来。

> 跟视频一样：**能不能下载取决于你对该图片是否有合法权利。** Gecko 不替你判断。

```powershell
# 只发现，不动文件
python gecko/core/range_crawler.py -u https://www.python.org/ -d 0 --image-scan

# 发现并把图下载回来，单张不超过 20MB
python gecko/core/range_crawler.py -u https://你的站点 -d 2 --image-scan --image-download --image-max-mb 20
```

第一条实测（python.org 首页）：找出 2 张——`python-logo.png`（`img@src`）和
`opengraph-icon-200x200.png`（`meta@og:image`）。该页面源码里确实只有 1 个 `<img>` 标签，
**没有漏也没有误报**。

## 第 5 章 · 命令行用法（可选）

习惯敲命令的话，功能和界面完全一致：

```powershell
# 最简：爬一个站，深度 2，5 线程
python gecko/core/range_crawler.py -u http://127.0.0.1:8000 -d 2 --threads 5

# 常用组合：提取注释 + 自适应限速 + 断点续爬
python gecko/core/range_crawler.py -u http://127.0.0.1:8000 -d 3 --comments --autothrottle --checkpoint

# 抓 SPA（JS 动态内容）+ 提取字段
python gecko/core/range_crawler.py -u http://127.0.0.1:8000 --render dynamic --select "标题=h1" --select "价格=.price"

# 伪装成 Chrome，并带上登录 Cookie
python gecko/core/range_crawler.py -u https://range.local --backend curl_cffi --impersonate chrome --cookie "session=abc"

# 自签名证书靶场
python gecko/core/range_crawler.py -u https://range.local --no-verify
```

界面服务的启动参数：

```powershell
python webui.py                      # 默认 8765 端口，自动开窗口
python webui.py --port 9000          # 换端口
python webui.py --window browser     # 用默认浏览器打开
python webui.py --window none        # 不开窗口，自己访问 http://127.0.0.1:8765
```

### 全部参数速查

| 参数 | 默认 | 说明 |
|---|---|---|
| `-u, --url` | 必填* | 种子地址（给了 `--url-file` 时可省略） |
| `--url-file` | 无 | **v3.9** URL 清单文件，一行一个地址；配合 `-d 0` 只抓清单里的地址 |
| `-d, --depth` | 3 | 爬取深度，0 = 只抓种子页 |
| `--threads` | 5 | 并发线程数 |
| `--delay` | 0 | 每次请求间隔秒数 |
| `--qps` | 0 | **v3.9** 全局每秒请求上限，0 = 不限（躲风控制最有效的旋钮） |
| `--max-pages` | 500 | 本次最多抓多少页 |
| `--timeout` | 10 | 单请求超时秒数 |
| `--retries` | 2 | 失败重试次数 |
| `--max-body-mb` | 3 | 单页最多读多少 MB |
| `--user-agent` | 自带 | 自定义 UA |
| `--cookie` | 空 | 登录态 Cookie |
| `--proxy` / `--proxy-file` | 空 | 单代理 / 代理列表轮换 |
| `--header` | 空 | 自定义请求头，可多次 |
| `--no-verify` | 关 | 跳过 HTTPS 证书校验 |
| `--backend` | auto | `auto` / `requests` / `curl_cffi` |
| `--impersonate` | 跟随后端 | `chrome` / `safari` / `firefox` / `chrome110` 等 |
| `--render` | 关 | `dynamic` / `stealthy`，浏览器渲染 |
| `--wait-selector` | 空 | 渲染时等待该 CSS 选择器出现 |
| `--network-idle` | 关 | 渲染时等网络空闲 |
| `--no-headless` | 关 | 渲染时显示浏览器窗口 |
| `--per-domain` | 0 | 每域名最大并发，0 = 不限 |
| `--autothrottle` | 关 | 自适应限速 |
| `--checkpoint` | 关 | 断点续爬 |

## 第 7 章 · 出问题先看这里

**Q：双击 bat 后一闪而过 / 报错说找不到 Python？**
A：按顺序排查，通常第一条就能解决：

1. **电脑没装 Python，或装了没加入 PATH**：去 python.org 装 3.9 以上版本，安装时务必勾选
   "Add Python to PATH"，装完重新双击。
2. **明明装过 Python 却还是失败**：多半是 py 启动器记着一条旧路径（例如以前装在 D 盘、
   后来删掉了）。启动脚本会依次尝试 `python`、`py -3`、`python3` 和常见安装目录，
   全都失败时手动建一次环境就行：
   ```powershell
   C:\你的路径\python.exe -m venv .venv
   ```
   建好后再双击 bat，会直接跳过这一步。
3. **窗口一闪而过，看不清报了什么错**：在 bat 所在的文件夹里按住 Shift 点右键，
   选"在此处打开 PowerShell 窗口"，输入 `.\启动Gecko.bat` 回车，
   报错信息就会停在屏幕上不再消失。

**Q：第一次启动卡在「检查依赖」很久？**
A：正常，第一次要下载依赖包。之后就有缓存了。如果卡超过 10 分钟，多半是网络问题，
可以手动执行 `python -m pip install -r requirements.txt` 看具体报错。

**Q：界面里「浏览器渲染」是灰的？**
A：没装浏览器依赖。直接双击 `安装可选增强.bat` 就行，它会自动装库并下载内核
（约 150MB，需要几分钟），装完重启工具即可。也可以手动执行：
```powershell
.venv\Scripts\python.exe -m pip install playwright patchright
.venv\Scripts\python.exe -m playwright install chromium
```

**Q：开了浏览器渲染，但日志说渲染失败？**
A：通常是没下载内核，执行 `python -m playwright install chromium`；
若提示超时，把「超时」调大（渲染本来就比普通请求慢）。

**Q：爬下来页面是空的 / 内容不全？**
A：内容由 JS 生成，改用「浏览器渲染」；或者页面需要登录，填上 Cookie。

**Q：中文全是乱码？**
A：工具已内置多层编码探测（响应头 → meta → UTF-8 → GB18030）。仍乱码的话，
说明站点用了自定义字体映射，用「字体反爬」工具处理。

**Q：爬了几百页还没完？**
A：把「最大页面数」调小、深度调成 2，或用 `--exclude` 排除无关路径；也可以直接点「停止」。

**Q：想完全重来一次？**
A：命令行加 `--fresh`，或删掉输出目录（或换个输出目录名）。

**Q：报告里 4xx 很多？**
A：4xx 说明地址存在但访问不了（404/403），属于正常发现结果；
如果全是 403，多半是被拦了，试试 `--backend curl_cffi --impersonate chrome`。

## 附：重新打包 exe

平时直接双击 `Gecko.exe` 就行，只有**改动了代码**（比如改界面、加功能）之后才需要重新打包。

1. 确认电脑上装了 Python，并进入项目文件夹；
2. 执行一次：`python tools/build_exe.py`
3. 等 1～2 分钟，新的 exe 会生成在 `dist/` 里，把它复制到项目根目录覆盖旧的即可。

> **注意**：exe 里打包的是「当前 `.venv` 里已经装好的东西」。
> 如果你想让 exe 也支持浏览器渲染或用上指纹伪装，要先双击 `安装可选增强.bat` 装好，
> 再重新打包。没装的话，exe 里这几项功能会显示为不可用，但不影响其他所有功能。
